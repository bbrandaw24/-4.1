## 三、系统怎么运行

可以把系统理解成一条生产线：设备层产生数据，MQTT 层负责传输，API 层负责处理，Web/未来 ArkTS 负责展示和控制。

1. 模拟器每 5 秒发布土壤、温度、光照数据到 MQTT sensor 主题。
2. Flask API 订阅 `farm/+/sensor/+`，校验消息并缓存最新状态。
3. 页面定时读取 API，显示当前值和趋势图。
4. 页面发送水泵 start/stop，API 生成 `command_id` 并发布 MQTT 控制主题。
5. 模拟器执行后回传 `status/pump`，API 收到回执后才把状态标为 `confirmed`。

## 五、传感器和灌溉模型

模拟器采用连续状态模型，不再让湿度、温度、光照完全随机跳变：

- 灌溉运行时，土壤湿度每 5 秒约上升 1.8 个百分点。
- 停止灌溉后，湿度缓慢回落，模拟蒸发和作物消耗。
- 温度、光照和空气湿度围绕基线小幅波动。

灌溉复测结果：土壤湿度 `49.79% -> 56.95%`，16 秒增加 `7.16` 个百分点；水泵停止回执延迟约 `2.6 ms`；10 小时历史接口正常返回。

## 六、页面怎么读

- **概览**：看设备、API/MQTT/AI 连接状态、最新传感器值和水泵状态。
- **趋势**：看 10 小时滚动数据，横轴为实际采样时间；土壤湿度纵轴为 `%`；温度和光照分别使用 `°C`、`kLux`。
- **设备**：看设备 ID、接入关系和连接状态。
- **控制区**：手动/自动模式、低湿度阈值、定时字段、告警和 MQTT 回执。

## 七、为什么 GitHub Pages 不能运行完整系统

GitHub Pages 只能托管静态 HTML/CSS/JavaScript，不能运行 Docker、MQTT、MySQL 或 Python API。因此 GitHub 用来公开代码、文档和报告，腾讯云用来运行完整系统。完整公网入口是 `http://43.156.230.129:8080/`。
